## Row scope and chart definitions

<Terms
  items={[
    ["Full", "Every loaded source row."],
    [
      "Peer-filtered",
      "Every other chart's filter, without the chart's own. A facet can narrow it further.",
    ],
    ["Globally filtered", "Every active chart filter."],
  ]}
/>

Bar category counts and bins use peer-filtered rows, so a chart never hides its own unselected bars. Named grouped summaries use globally filtered rows.

Saved settings carry each chart type. The registry maps `scatter` to the scatter definition and `bar` to the bar definition. Each definition supplies its settings and renderer. The scatter plan maps effective X and Y values into points and axis geometry; Canvas draws the points and SVG draws the axes and brush. The bar plan computes category counts, bins, or grouped values; SVG draws its bars and axes.

## Interaction and saved state

A brush or bar selection updates that chart’s filter. Crossfilter then updates linked views using their peer-filtered rows. Charts expose their plans to trace, so a mark can be followed back to its rows; see <DocsLink topic="trace">Trace a mark</DocsLink>.

The package sends changed workspace settings through `onStateChange`. That saved structure includes chart and calculation settings, but not the source rows. The host owns durable storage and supplies the rows again when it restores the workspace.
