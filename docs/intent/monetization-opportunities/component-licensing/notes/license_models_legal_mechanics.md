All web sources accessed 2026-10-10 unless noted. Nothing here is legal advice; items that need a lawyer are marked **[needs a lawyer]**. Dependency license data was read directly from the installed packages in this worktree's `node_modules` (pnpm store) on 2026-10-10, which is primary-source evidence for the exact installed versions.

Repo facts relevant to several questions (checked locally 2026-10-10): `packages/explorEDA/package.json` has no `license` field and `publishConfig.access: "public"`; there is no `LICENSE` file at the repo root or in `packages/explorEDA`; `git shortlog -sn HEAD` shows authors "Byron Wall" (708 commits), "--worktree" (102), "Claude" (21) and "github-actions[bot]" (7), i.e. no outside human contributors.

## Key question 1: License models and their tradeoffs for a solo maintainer with no users yet

### Takeaway
The models split into three families with very different enterprise-review outcomes: (1) MIT core + paid tier or paid services (AG Grid, MUI X, React Flow) keeps SEO/adoption and clears legal review, but monetizes only the paid slice; (2) non-OSI source-available (Handsontable-style non-commercial, PolyForm, FSL, BSL) is routed to legal review at most companies and some policies say "consult the OSPO before any use"; (3) AGPL dual licensing is the one model that large companies reject outright by written policy (Google: AGPL "MUST NOT be used"), which is exactly what makes the paid license sell for a self-hosted product but is a poor fit for a client-side component embedded in customers' SaaS. The best-documented maintainer retrospectives (Handsontable, Sentry, HashiCorp, Fluent Assertions, Tiptap) show the switch itself is survivable but abrupt library relicensing triggers community backlash and forks.

### Cited Findings

**Source-available, free for non-commercial, paid commercial (Handsontable style)**
- Handsontable announced on March 4, 2019 that it was dropping MIT; version 7.0.0 (March 6, 2019) merged Handsontable Pro into CE and replaced MIT with a custom "free for non-commercial and evaluation" license. The maintainers' reason: "the ratio of commercial to free users is about 1 to 25," which did not cover costs; commercial users must buy a license or stay on 6.2.2. — [Handsontable blog, 2019](https://handsontable.com/blog/?p=1263)
- Handsontable's current docs describe the model as two proprietary license types (Non-Commercial License and Commercial License Agreement); "You are required to specify which type of license you use"; in commercial settings use is "strictly limited to evaluation, development and testing," and "you can't enter the production stage if your project is in any way connected with your commercial activity." Commercial keys are obtained by contacting sales. Last permissive version was 6.2.2 (Dec 19, 2018). — [Handsontable software license docs](https://handsontable.com/docs/react-data-grid/software-license/)
- Handsontable's 7.0.0 release notes described the result as "source-available" rather than "open source." — [Handsontable blog](https://handsontable.com/blog/?p=1299)
- Fluent Assertions (.NET library) switched in January 2025 from Apache 2.0 to the Xceed Community License (non-commercial only; paid Xceed license otherwise, reported at $129.95 per seat for v8+), one day after announcing an Xceed partnership; reaction was "not well received," with the suddenness and contributor-rights questions drawing criticism. — [DevClass, Jan 16 2025](https://devclass.com/2025/01/16/another-open-source-project-shifts-to-restrictive-license-fluent-assertions-following-xceed-partnership); [Aaron Stannard, "Relicense or die"](https://aaronstannard.com/relicense-or-die/)

**Open core: MIT + paid tier (AG Grid / MUI X style)**
- AG Grid Community is "Free for everyone, including production use - no licence required"; Enterprise "Requires a licence to use in production"; licences are "available on a per-developer, per-deployment basis." — [AG Grid community vs enterprise](https://www.ag-grid.com/javascript-data-grid/community-vs-enterprise.md)
- AG Grid pricing: Enterprise $999/developer, Charts Enterprise $499, bundle $1,498; perpetual licence with one year of updates; 30-day trial. — [AG Grid pricing](https://www.ag-grid.com/license-pricing/)
- MUI X pricing (annual plans shown): Pro $299/yr/dev, Premium $599/yr/dev, Enterprise $1,399/yr/dev from 15 seats; perpetual option includes 12 months of maintenance with renewal discounts of 50%/35%/15% depending on timing; annual key is "perpetual in production." — [MUI pricing](https://mui.com/pricing/)
- MUI X seat rule: licenses must match "the number of concurrent developers who contribute front-end changes"; back-end developers who do not touch front-end code do not need seats; developers maintaining an internal UI library wrapping MUI X count. — [MUI X licensing](https://mui.com/x/introduction/licensing/)

**MIT library + paid services/examples (React Flow style)**
- React Flow: "open-source MIT-licensed software, and it will be forever"; companies pay via GitHub Sponsors or a React Flow Pro subscription for Pro Examples/Templates, prioritized issues, and support hours; maintainers (webkid GmbH / xyflow, Berlin) work on it full-time. — [React Flow Pro](https://www.reactflow.dev/pro); [React Flow Pro pricing](https://reactflow.dev/pro/pricing)
- Tiptap: core editor MIT; on June 6, 2025 Tiptap open-sourced eight former Pro extensions (Details, Emoji, DragHandle, FileHandler, InvisibleCharacters, Mathematics, TableOfContents, UniqueID) under MIT because they "are no longer at the center of our business," and simultaneously sunset the Tiptap Cloud free tier. — [Tiptap release notes, June 2025](https://tiptap.dev/blog/release-notes/were-open-sourcing-more-of-tiptap)
- Tiptap Pro license: "ongoing, non-exclusive license to use the Tiptap Pro extensions, as long as you are an active subscriber." — [Tiptap Pro License](https://tiptap.dev/docs/pro-license)

**Dual AGPL + commercial (Cal.com style)**
- Cal.com moved from MIT to AGPLv3 and put enterprise code in an `/ee` folder under a separate "Enterprise License"; "the content of the /ee folder is copyrighted, so you can't use it to host your own version without first getting a proper license"; motive included guarding "against large companies taking over the project." — [Cal.com blog](https://cal.com/blog/changing-to-agplv3-and-introducing-enterprise-edition)
- Lago chose AGPLv3 (2022) with a dual model: a company forking to sell a product "must contribute back, either by sharing its own source code with the community, or by buying a commercial license"; a third-party check on 2026-08-26 still reported Lago as AGPL-3.0 (no license change found). — [Lago blog](https://www.getlago.com/blog/open-source-licensing-and-why-lago-chose-agplv3); [Flexprice glossary (competitor; verify)](https://flexprice.io/glossary/open-source-billing)
- Google policy: "Code licensed under the GNU Affero General Public License (AGPL) MUST NOT be used at Google"; reasoning is that AGPL obligations trigger when software "can be accessed over a remote network interface," and "The risks heavily outweigh the benefits." — [Google Open Source AGPL policy](https://opensource.google/documentation/reference/using/agpl-policy)
- iText (AGPL dual-licensor) states most companies cannot agree to AGPL's copyleft terms and a commercial license removes those obligations. — [iText legal (archived)](https://web-archive.nli.org.il/National_Library/mp_/https://itextpdf.com/legal)

**Fair Source: FSL 1.1 (Sentry)**
- FSL overview: "You can do anything with FSL software except undermine its producer"; each version converts to MIT or Apache 2.0 two years after release; "FSL software can be adopted at organizations where AGPL is outside of policy"; FSL is positioned as an evolution of BSL whose Additional Use Grant and four-year term are called flaws. — [fsl.software](https://fsl.software/)
- Sentry's reasoning: BSL's Additional Use Grant is "a giant fill-in-the-blank," so every BSL project is effectively a different license and compliance teams review each individually; the 4-year default is too long; FSL also "is not suited to businesses based on charging for on-premise use or library embedding." — [Sentry blog, Introducing FSL](https://blog.sentry.io/introducing-the-functional-source-license-freedom-without-free-riding/)
- Sentry applies the stricter FSL only to the web app code; its licensing page says FSL permits almost everything except offering a competing commercial version, lapsing after a two-year grace period. — [open.sentry.io/licensing](https://open.sentry.io/licensing)
- Named FSL/Fair Source adopters (2024 sources): Codecov, CodeCrafters, GitButler, Keygen, PowerSync, AnswerOverflow, Convex, Ptah.sh. Fair Source recognizes FSL, Keygen's Fair Core License (FCL) and BSL. Fair.io recommends FSL as "ideal for companies with a SaaS business model." — [Sentry: Sentry is now Fair Source](https://blog.sentry.io/sentry-is-now-fair-source); [fair.io FAQ](https://fair.io/faq/); [fair.io join](https://fair.io/join/)

**BSL 1.1 (HashiCorp)**
- HashiCorp switched Terraform, Vault, Consul, Nomad, Boundary and Waypoint from MPL-2.0 to BSL 1.1 on August 10, 2023; the restriction targets "competitive offering[s]." OpenTofu (fork of the last MPL version) was accepted by the Linux Foundation on Sept 20, 2023; HashiCorp sent a cease-and-desist that OpenTofu rejected because the code was already MPL-licensed. IBM acquired HashiCorp (~$6.4B, announced April 24, 2024; one source says closed Feb 27, 2025) and did not reverse the BSL. — [Vivian Voss, "The terms you did not sign"](https://vivianvoss.net/blog/the-terms-you-did-not-sign); [The New Stack](https://thenewstack.io/with-ibms-open-source-roots-terraform-could-be-free-again/); [The New Stack, OpenTofu reconciliation](https://thenewstack.io/opentofu-amiable-to-a-terraform-reconciliation/)
- BSL is "not approved by either the OSI or the FSF" and "not GPL compatible"; after a period "generally four years" code becomes GPLv2-or-later or compatible. — [Wikipedia: Business Source License](https://en.wikipedia.org/wiki/Business_Source_License)

**Enterprise legal-review friction**
- An OSPO FAQ template says SSPL, BSL, Elastic License and BUSL "are not open source licenses under the OSI definition," "may seem permissive but come with commercial limits," and instructs "Consult the OSPO before any use"; its workflow is approved list → otherwise request to OSPO → legal review → registry. — [OSPO Alliance FAQ](https://ospo-alliance.org/faq/licences/05-approved-licenses/)
- Sentry's own description of the "lightweight" restriction: "you simply cannot commercialize it as a competing service." — [Sentry: Let's talk about open source](https://blog.sentry.io/lets-talk-about-open-source)
- A vendor blog (Roboflow, March 2026) argues the license on a component can decide "whether a deal survives legal review" when AGPL is involved. — [Roboflow](https://blog.roboflow.com/why-agpl-3-0-is-a-risk-for-computer-vision-teams/)

**Syncfusion community license (threshold-based free tier, as a reference point for PolyForm Small Business style)**
- Syncfusion's free Community License requires less than $1M USD annual gross revenue, 5 or fewer developers and 10 or fewer total employees. — [Syncfusion community license story](https://www.syncfusion.com/web-stories/easy-way-to-claim-free-syncfusion-community-license)

### Inferences
- Enterprise procurement is the real discriminator. Open core (MIT core) is the only model among these whose free tier passes allowlists untouched; FSL/BSL/PolyForm/Handsontable-style licenses all land in "consult legal," and AGPL is the only one with documented blanket bans. For a component that customers embed in their own commercial SaaS, a paid proprietary EULA for the paid tier is what every incumbent (AG Grid, MUI X, Handsontable, Highcharts, amCharts, FullCalendar) actually uses; none of them ship the paid tier under FSL/BSL/PolyForm.
- Sentry explicitly says FSL is not suited to "library embedding" businesses. FSL/BSL make sense when the threat is a competing hosted service; for a component, the threat is non-payment by embedders, which FSL's "Competing Use" definition does not address (internal use and embedding in a non-competing product are Permitted Purposes).
- With zero users and no outside contributors, there is no relicensing backlash risk today; the Fluent Assertions and HashiCorp stories are warnings about switching later, which argues for choosing the restrictive-or-open-core split before adoption, not after.
- SEO/GitHub discovery: no study was found that quantifies star or adoption loss from a license switch (see Gaps). The qualitative evidence (Handsontable kept its market; Fluent Assertions and HashiCorp got forks/backlash) suggests the switch matters less than how it is done and whether a free tier remains.
- Piracy/enforcement effort: every vendor surveyed validates keys locally and tolerates leaked keys (MUI: "designed to be public"), so enforcement is essentially contractual plus occasional DMCA (Stimulsoft, Aspose examples below). A solo maintainer should budget zero technical enforcement and rely on the EULA plus nag UI.

### Gaps
- No primary quantitative data on how a source-available license affects GitHub stars, npm downloads or SEO; the search returned only unrelated star-loss studies.
- No Sentry "one year later" FSL retrospective was found; the 2024 "Sentry is now Fair Source" post is the latest first-party write-up located.
- No first-party Lago license change was found (Lago appears to remain AGPLv3); the prompt's premise may be mistaken.
- No published real-company OSPO policy naming PolyForm or non-commercial licenses specifically; only the OSPO Alliance template and Google's AGPL policy.

## Key question 2: Clauses that matter in commercial component licenses and in FSL/BSL/PolyForm

### Takeaway
Commercial component EULAs converge on: per-developer seats defined broadly (anyone working on code that touches the component), a "named application" or single/multiple application scope, a separate OEM/redistribution add-on, SaaS treated as permitted deployment (not redistribution) but customer-installable products treated as OEM, perpetual rights to versions released during the paid term, 30-day cure termination, as-is warranty, liability capped at fees paid, and (Highcharts) annual audit rights. FSL/BSL/PolyForm are short public licenses with no seat concept; they govern the free tier only.

- Non-commercial license PDF (Handsoncode Non-Commercial License Agreement) outline: "1. Copyright notice; 2. Copyright license; 3. Miscellaneous; 4. Disclaimer and limitation of liability." Full text could not be extracted (see Gaps). — [Handsontable non-commercial license PDF](https://handsontable.com/static/licenses/non-commercial/v5/handsontable-non-commercial-license.pdf)
- Subscription License Agreement v2: "Authorized User" is a Developer and/or an End User; a Developer is the Licensee's "employee, agent, or independent contractor who personally carries out development of the Software"; use of Deliverables indicates acceptance. — [Handsontable subscription license agreement v2 (PDF)](https://www.Handsontable.com/static/licenses/subscription/handsontable-subscription-license-agreement-v2.pdf)
- Reseller summary of the commercial terms: priced per developer, "for 1 application ... unlimited end users for SaaS/Internal deployment"; developer definition includes "front-end and back-end developers, code reviewers, and testers"; "you must stop using the software if you choose not to renew." — [ComponentSource Handsontable listing (reseller; secondary)](https://www.componentsource.com/product/handsontable/buy/1297253)
- Key mechanics (also relevant to Q7): missing/invalid key blocks the grid with an uncloseable modal; perpetual keys are checked against the build date of the installed version ("Versions released on or before the maintenance date work indefinitely, including offline"); subscription/trial keys compare the stored expiration date with the current UTC date; "Validation compares dates and doesn't contact any server." — [Handsontable license key docs](https://handsontable.com/docs/react-data-grid/license-key/)

**AG Grid Enterprise EULA**
- "Licensee Developers" covers employees, workers and contractors (of Licensee and Affiliates) authorised to build software including the Software; Single Application Developer Licence permits "one Application" (successive versions count as the same Application); Multiple Applications Developer Licence permits "an unlimited number of Applications." — [AG Grid Enterprise licence text via ScanCode LicenseDB](https://scancode-licensedb.aboutcode.org/ag-grid-enterprise.html)
- Deployment Licence Add-On "permits the Licensee to sub-licence the Software in accordance with these Terms," limited by number of Production Environments, defined as "a computer, server, collection of servers, a data centre, a cloud instance, container or similar" where services are made available to customers; sub-licence terms must be written and at least as restrictive. Redistribution otherwise prohibited: "shall not redistribute the Software Materials or any Modifications other than as expressly permitted." — same source; also [AG Grid EULA v12.0](https://www.ag-grid.com/eula/AG-Grid-Enterprise-License-v12.0.html)
- Access is "by provision of an activation key and any login details"; support 12 months with 10 Support Requests per Licensee Developer; termination for material breach unremedied 30 days after notice; no warranty that software "WILL BE UNINTERRUPTED OR ERROR-FREE"; aggregate liability capped at "THE GREATER OF" fees payable or $5,000; no audit clause found; governed by English law with exclusive English jurisdiction (injunctive relief anywhere). — [ScanCode AG Grid text](https://scancode-licensedb.aboutcode.org/ag-grid-enterprise.html)
- Sample AG Grid key text embeds the licence scope: a company "has been granted a Deployment License Add-on for {1} Production Environment," "All Front-End JavaScript developers working on {AcmeApp} need to be licensed," the covered version, and a legal contact for misuse reports. — [AG Grid license install](https://www.ag-grid.com/javascript-data-grid/license-install/)

**Highcharts (Highsoft Standard License Agreement)**
- Developers: "any unnamed person, whether an employee, contractor, consultant or other person working on behalf of Licensee" (s.1); exceeding the stated count "shall be considered a material breach" (3.2.1).
- Internal License (4.1): "internal purposes only." SaaS License (4.2): approved External Applications and Public Websites; Customer Installations under it are "deemed invalid and shall be considered a material breach"; non-reusable (cannot move to another application). OEM License (4.3): "non-exclusive, perpetual (for applicable Releases), non-reusable, worldwide right to install" inside a Licensee Product supplied via Customer Installations.
- Advantage (updates/support) auto-enrolled for 12 months in the fee (5.1); opting out keeps "a perpetual License to the Releases ... to which Licensee has lawfully gained access" (5.4); fixed Advantage periods up to five years (5.2).
- Termination for uncured material breach after 30 days (14.3); perpetual rights may lapse on termination for breach (3.2.3). Warranty: "perform substantially in accordance with Highsoft's written specifications" (10.2), sole remedy re-supply/correct (10.3), otherwise as-is (11). Liability excludes indirect/lost profits and is capped at fees in the last 12 months (11). Audit: "once per year during the term" and once in the five years after, ten days' notice, Highsoft bears cost if no discrepancy (18.2). Non-commercial use is under separate terms. — [Highcharts license](https://shop.highcharts.com/license)

**amCharts (reseller fact sheet)**
- Free license has the same functionality but "requires an amCharts attribution on all charts"; all licenses perpetual for the current major version with free minor updates; Basic covers public sites, OEM covers redistributable apps, SaaS is for login-gated sites; "each developer must have an individual, valid license." — [ComponentSource amCharts fact sheet (reseller; secondary)](https://www.componentsource.com/product/amcharts/factsheet)

**FullCalendar Premium**
- Four routes: Commercial (allows source modification but not redistribution of modifications); Non-commercial for registered non-profits under CC BY-NC-ND with key `CC-Attribution-NonCommercial-NoDerivatives` (governments and universities excluded); AGPLv3 projects (frontend and backend) with key `AGPL-My-Frontend-And-Backend-Are-Open-Source` ("As of v7, AGPLv3 replaces GPLv3"); other open-source projects do not hardcode a key and let installers supply their own. Unset key: "This will cause a warning message to show on the widget." — [FullCalendar license](https://fullcalendar.io/license)

**FSL-1.1-MIT template text**
- "A Permitted Purpose is any purpose other than a Competing Use," expressly including internal use and access, non-commercial education, non-commercial research, and professional services to a licensee. "A Competing Use means making the Software available to others in a commercial product or service that: 1. substitutes for the Software; 2. substitutes for any other product or service we offer using the Software that exists as of the date we make the Software available; or 3. offers the same or substantially similar functionality as the Software." Redistribution must keep copyright notices and include the terms. Patent license ends on a patent claim. "THE SOFTWARE IS PROVIDED 'AS IS' AND WITHOUT WARRANTIES OF ANY KIND." Future license: "We hereby irrevocably grant you an additional license to use the Software under the MIT license that is effective on the second anniversary of the date we make the Software available." — [FSL-1.1-MIT template (getsentry/fsl.software)](https://raw.githubusercontent.com/getsentry/fsl.software/main/FSL-1.1-MIT.template.md)

**BSL 1.1**
- Parameters: Additional Use Grant ("The Licensor may make an Additional Use Grant, above, permitting limited production use"); Change Date, with conversion no later than "the fourth anniversary of the first publicly available distribution of a specific version"; Change License must be "GPL Version 2.0 or any later version, or a license that is compatible with GPL Version 2.0" (additional Change Licenses allowed); violation "will automatically terminate your rights under this License for the current and all other versions"; "LICENSOR HEREBY DISCLAIMS ALL WARRANTIES AND CONDITIONS, EXPRESS OR IMPLIED." — [MariaDB BSL 1.1](https://mariadb.com/bsl11/)

**PolyForm Noncommercial 1.0.0**
- "Any noncommercial purpose is a permitted purpose"; personal uses ("Personal use for research, experiment, and testing for the benefit of public knowledge," study, hobby, amateur pursuits, religious observance) and noncommercial organizations ("any charitable organization, educational institution, public research organization," public safety/health/environmental/government bodies regardless of funding). Notices: "You must ensure that anyone who gets a copy of any part of the software from you also gets a copy of these terms" plus any "Required Notice:" lines. 32-day cure after first written notice; fair use preserved; as-is, no liability. — [PolyForm Noncommercial 1.0.0](https://polyformproject.org/licenses/noncommercial/1.0.0)

**PolyForm Small Business 1.0.0**
- Permitted for a company with "fewer than 100 total individuals working as employees and independent contractors" and prior-year revenue under 1,000,000 USD (2019 dollars, CPI-adjusted). Same notices, 32-day cure, patent defense, no sublicensing/transfer, as-is terms. — [PolyForm Small Business 1.0.0](https://polyformproject.org/licenses/small-business/1.0.0)

**PolyForm Shield 1.0.0**
- Any purpose except "providing any product that competes with the software"; products compete even with different interfaces/platforms or if free; a product marketed as a practical substitute "definitely competes"; if the licensor later competes with your product you may keep using earlier versions; a buyer of the licensor's line of business can enforce the Noncompete. — [PolyForm Shield 1.0.0](https://polyformproject.org/licenses/shield/1.0.0)

### Inferences
- The clause set a solo seller must draft for a paid tier (and should have reviewed) **[needs a lawyer]**: (a) Developer/seat definition (copy the MUI X "front-end contributors" or Highcharts "any person working on behalf" style, pick one deliberately); (b) application scope (single vs. multiple applications); (c) explicit statement that SaaS/web deployment to end users is permitted and not redistribution, with a separate OEM/redistribution add-on for customer-installable or resold products; (d) perpetual-rights-to-versions-released-during-term language; (e) termination with cure; (f) as-is warranty and liability cap at fees paid; (g) governing law and venue; (h) whether to include audit rights (Highcharts does; AG Grid does not).
- For the free tier, a published public license (PolyForm Noncommercial, PolyForm Small Business, or FSL) can be adopted verbatim without drafting; the PolyForm texts already contain notice, cure and patent clauses. PolyForm Small Business's 100-person/$1M thresholds mirror Syncfusion's community-license thresholds.
- Highcharts' "SaaS License ... Customer Installations are deemed invalid" and amCharts' Basic/SaaS/OEM split show the industry norm: pricing tiers hinge on whether the customer's customers install the code, not on whether it runs in a browser.

## Key question 3: Runtime dependency license compatibility

### Takeaway
Every direct runtime dependency in `packages/explorEDA/package.json` is MIT, ISC or Apache-2.0 (verified from installed `package.json` `license` fields and LICENSE files on 2026-10-10); none is GPL/LGPL/MPL, and none uses a Creative Commons license. All are compatible with shipping inside a proprietary or source-available package, subject to carrying the copyright/permission notices (MIT/ISC) and the Apache-2.0 license copy plus crossfilter2's NOTICE. The only copyleft anywhere in the production tree is `lightningcss` (MPL-2.0), pulled in by `@tailwindcss/postcss`, which is a build-time tool mislabeled as a runtime dependency; `world-atlas` data derives from Natural Earth, which is public domain with optional attribution.

## Key question 4: What "public GitHub repo with no LICENSE file" means, and whether the author can relicense

### Takeaway
Without a license, default copyright applies: viewers may look at and fork the repo on GitHub under the Terms of Service, but have no permission to use, modify or redistribute the code, and people who installed the npm package (which also carries no `license` field) have no written license either. Because the git history shows only the author plus bot/agent commits and no outside human contributors, the author holds all copyright and can choose any license going forward; a CLA is only needed once outside contributions arrive.

### Cited Findings
- "the work is under exclusive copyright by default"; without a license "nobody else can copy, distribute, or modify your work without being at risk of take-downs, shake-downs, or litigation"; users have "no permission from the creators of the software to use, modify, or share the software"; publishing on GitHub means "you allow others to view and fork your repository," but "this does not imply that you are permitted to use, modify, or share the software for any purpose." Advice: add a copyright notice stating no license is offered, and for contributions "explore adding a contributor agreement to your project with your lawyer." — [choosealicense.com no-permission](https://choosealicense.com/no-permission/)
- GitHub docs: "without a license, the default copyright laws apply," "no one may reproduce, distribute, or create derivative works from your work"; under the ToS "other users of GitHub.com have the right to view and fork your repository"; "You're under no obligation to choose a license." — [GitHub: Licensing a repository](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/licensing-a-repository)
- GitHub ToS D.5: "By making a repository public, you grant other Users a nonexclusive, worldwide license to use, display, perform and reproduce (by forking) Your Content through the Service as permitted by GitHub's functionality." D.6: "Whenever you add Content to a repository containing notice of a license, you license that Content under the same terms, and you agree that you have the right to license that Content under those terms." — [GitHub Terms of Service](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service)
- Local repo state (2026-10-10): no LICENSE file; no `license` field in `packages/explorEDA/package.json`; `git shortlog -sn HEAD`: Byron Wall 708, "--worktree" 102, Claude 21, github-actions[bot] 7.

### Inferences
- Existing npm installers of `exploreda` have, strictly, no license to use it; practically, an author choosing a license now can grant one retroactively by publishing a license that covers past versions (or by republishing). A clear statement in the README/npm page avoids the "oversight" assumption choosealicense warns about.
- GitHub ToS D.6's inbound=outbound rule only operates when the repo "contain[s] notice of a license." With no license, future outside PRs would arrive with no license at all, which is the strongest reason to add a license and a CLA/DCO before accepting contributions.
- With no outside contributors, relicensing is a unilateral act; nothing was found suggesting otherwise. **[needs a lawyer]** only if any commits were made in the course of employment for someone else, or if the "--worktree"/"Claude" commit identities mask any third-party authorship.

### Gaps
- No source addresses the specific status of npm package consumers of an unlicensed package; the GitHub guidance covers repositories, and npm's terms were not researched.

## Key question 5: CLA vs DCO and lightweight tooling

### Takeaway
A CLA (with a broad license grant or copyright assignment) is what preserves the maintainer's right to relicense or sell commercial licenses on contributed code; a DCO is only a per-commit certification that the contributor may submit under the project's current license and grants no relicensing right. Both are enforceable with free GitHub apps (CLA Assistant from SAP; the DCO app).

### Cited Findings
- DCO 1.1 points: "(a) The contribution was created in whole or in part by me and I have the right to submit it under the open source license..."; "(b) ... based upon previous work that, to the best of my knowledge, is covered under an appropriate [open source license]..."; "(c) ... provided directly to me by some other person who certified (a), (b) or (c)..."; "(d) I understand and agree that this project and the contribution are public and that a record of the contribution ... is maintained indefinitely and may be redistributed consistent with this project or the open source license(s) involved." The DCO grants no license and does not transfer copyright or grant relicensing rights. — [developercertificate.org](https://developercertificate.org/)
- "the Project will receive a broader set of rights that provides flexibility to change the terms of the applicable Project License, or potentially to license a contribution or Work on completely different terms, without the need to obtain new licenses or consents from contributors" (CLA); a Django maintainer noted switching to DCO would mean the foundation "loses the ability to relicense Django in the future." — [FINOS OSR: CLAs and DCOs](https://osr.finos.org/docs/bok/Artifacts/CLAs-And-DCOs); [Django forum: CLA vs DCO](https://forum.djangoproject.com/t/cla-vs-dco-for-django-contributors/42399)
- Opensource.com rule of thumb: "if you want to minimize the barriers for contribution while still requiring your contributors to pinky swear that they're submitting their own work, then look at using a DCO"; CLA benefit "if the current license is found to be inadequate and you can't contact the hundreds of people who have contributed." — [opensource.com: CLA vs DCO](https://opensource.com/article/18/3/cla-vs-dco-whats-difference)
- CERN: a CLA "can include Copyright (©) transfer ... This generally eases the life of project managers (eg in case of re-licensing)"; CERN recommends DCO for external contributions. — [CERN OSPO: CLAs and DCOs](https://ospo.docs.cern.ch/recommendations/CLAs-and-DCOs)
- CLA Assistant: store the CLA as a GitHub Gist, link it to the repo, contributors sign in with GitHub and accept on their first PR; site is "copyright SAP SE" and "Powered by the open source CLA-assistant project." — [cla-assistant.io](https://cla-assistant.io/)
- DCO GitHub app (Probot): requires every commit to carry a `Signed-off-by` line whose email matches the author, excluding bots and merges; "creates a check indicating whether or not commits in a Pull Request do not contain a valid Signed-off-by line"; admins get an override button; enforce via branch protection "Require status checks to pass"; `.github/dco.yml` with `require: members: false` exempts org members; contributors use `git commit -s`. FINOS notes "DCO2" as a successor app. — [probot/dco](https://github.com/probot/dco/); [dcoapp/app](https://www.github.com/dcoapp/app); [FINOS DCO](https://community.finos.org/docs/governance/Software-Projects/dco)
- Fluent Assertions' relicensing left "users ... questioning contributor rights," illustrating the DCO/no-agreement failure mode. — [DevClass](https://devclass.com/2025/01/16/another-open-source-project-shifts-to-restrictive-license-fluent-assertions-following-xceed-partnership)

### Inferences
- For a dual-licensed or source-available component where the maintainer intends to sell commercial licenses on the whole codebase, a CLA with a broad, irrevocable, sublicensable grant (or assignment) is required; a DCO alone would leave contributed code licensed only under the public license and the maintainer unable to sell it proprietary. **[needs a lawyer]** for the CLA text itself; common starting points are the Apache ICLA or Harmony-style agreements (not fetched here).
- CLA Assistant (Gist + GitHub app, free) is the lowest-effort setup for a solo maintainer; a DCO bot can be layered on top but does not replace the CLA for relicensing purposes.

### Gaps
- No pricing/limits page for CLA Assistant or the "Lite" GitHub Action variant was fetched; cost appears to be free but is not stated on the site.
- Specific CLA templates (Apache ICLA, Harmony) were not reviewed.

## Key question 6: Merchant of record options for a solo seller

### Takeaway
All-in MoR pricing clusters at 5% + $0.50 per transaction (Paddle, Lemon Squeezy, Polar Starter) with international (+1.5%) and subscription (+0.5%) surcharges on some; Polar offers lower per-transaction rates for a monthly fee and ships built-in license keys; Gumroad is 10% + $0.50; FastSpring is quote-based; Stripe direct is 2.9% + $0.30 with Stripe Tax at 0.5% (calculation only, no MoR) or Stripe Managed Payments at +3.5% (true MoR, about 6.4% + $0.30 all-in). ## Key question 7: License key mechanics in npm packages

### Takeaway
Every surveyed vendor (AG Grid, Handsontable, MUI X, Syncfusion, amCharts, FullCalendar) validates keys entirely client-side with no network call: the key is a signed/encoded string containing a date (expiry or "maintenance end") and plan metadata, checked against either the current date (subscription/trial) or the build/release date of the installed package (perpetual). Failure modes range from gentle (MUI watermark + console warning, component keeps working; AG Grid 5-second watermark + console warnings; FullCalendar on-widget warning; amCharts attribution link) to hard (Handsontable uncloseable modal for missing/invalid keys, blocking screen after a trial's grace period). The least hostile pattern that still converts is MUI's: public key by design, perpetual-in-production for versions released during the term, nag only on failure.

### Cited Findings
- MUI X: "The license key is checked without making any network requests"; on failure "the component displays a watermark and provides a console warning in both development and production," components still work; failure types: missing key, package version released after term end, expired annual key, plan mismatch, component not covered, invalid format; key "is designed to be public," and MUI asks licensed users "not to actively publicize their license key"; the key must be set before the first component renders. — [MUI X licensing](https://mui.com/x/introduction/licensing/)
- MUI renewal: MUI "cannot extend the validity of an existing license key, meaning the key will always expire," so each renewal issues a new key that must be swapped; multi-year licenses reduce swaps. — [MUI support: Renewal license key](https://support.mui.com/hc/en-us/articles/24406138128668-Renewal-license-key)
- AG Grid: key set once statically before the first grid; checked "without making any network calls"; without a valid licence "your console log will display a series of warnings and the grid will show a watermark for 5 seconds"; Enterprise can be tested locally without a licence, and a trial licence removes the watermark/warnings in production; the key text embeds licensed application, developer scope, deployment add-on and version. — [AG Grid license install](https://www.ag-grid.com/javascript-data-grid/license-install.md); [AG Grid licensing](https://www.ag-grid.com/react-grid/licensing/)
- Handsontable: `licenseKey: 'non-commercial-and-evaluation'` keyword silences everything for non-commercial use; missing/invalid key blocks the grid with an uncloseable modal; expired perpetual key compared against the installed build date ("Versions released on or before the maintenance date work indefinitely, including offline"; newer versions log an error and show a notice below the table but keep working); subscription keys warn before and error after the UTC expiry date with the grid still working; trial keys show a badge, then a blocking screen after the grace period; "Validation compares dates and doesn't contact any server." — [Handsontable license key docs](https://handsontable.com/docs/react-data-grid/license-key/)
- Syncfusion: "license validation is done offline during application execution and does not require internet access"; keys are "version and platform specific"; trial-built apps show a banner that "a valid license key must be included" to remove; free Community License for companies under $1M revenue, 5 developers, 10 employees. — [Syncfusion licensing FAQ](https://ej2.syncfusion.com/aspnetmvc/documentation/licensing/licensing-troubleshoot); [Syncfusion forum (trial banner)](https://www.syncfusion.com/forums/183229/this-application-was-built-using-a-trial-version-of-syncfusion-essential-studio-to-remove); [Syncfusion community license](https://www.syncfusion.com/web-stories/easy-way-to-claim-free-syncfusion-community-license)
- amCharts: free license "offers the same functionality as the paid licenses, but requires an amCharts attribution on all charts"; licenses perpetual per major version; keys delivered by email and in "My Licenses." — [ComponentSource amCharts fact sheet](https://www.componentsource.com/product/amcharts/factsheet); [amCharts accessing licenses](https://www.amcharts.com/support/accessing-licenses/)
- FullCalendar: `schedulerLicenseKey` option; undefined key means "unlicensed" and "will cause a warning message to show on the widget"; honor-system keys for AGPL projects and non-profits; other open-source projects leave the key out so installers supply their own. — [FullCalendar license](https://fullcalendar.io/license)
- Enforcement precedents: Aspose "regularly checks for license files that have been made public and may blacklist these licenses without warning"; Stimulsoft used GitHub DMCA for an "illegally generated license key" in a public repo; GitHub processes such notices under its prohibition on sharing unauthorized product licensing keys. — [Aspose report license abuse](https://about.aspose.com/security/report-license-abuse); [GitHub DMCA repo mirror (Stimulsoft notice)](https://git.randommeaninglesscharacters.com/github/dmca/commit/24b627b3beb9477d85f889144a78daec02edc9f5)
- Private registries: Tiptap Pro uses the `@tiptap-pro` scope on a private registry with a per-user non-expiring token supplied via `.npmrc`/`TIPTAP_PRO_TOKEN`, with a dedicated CI user recommended; select extensions also require an active subscription. — [Tiptap Pro extensions guide](https://tiptap.dev/docs/guides/pro-extensions)
- Font Awesome Pro: `@fortawesome:registry=https://npm.fontawesome.com/` plus `_authToken` from `FONTAWESOME_NPM_AUTH_TOKEN`; Font Awesome's earlier instructions leaked tokens into lockfiles via the registry URL, which they changed; "An npm token does not provide access to your fontawesome.com account." — [Font Awesome packages setup](https://fontawesome.com/docs/web/setup/packages); [Font Awesome blog: locking the vault](https://blog.fontawesome.com/locking-the-vault-on-font-awesome-npm-tokens-2/)
- Bryntum: licensed packages on `https://npm.bryntum.com` (EU) / `npm-us.bryntum.com` (US) with `npm login` (email with `@` replaced by `..`); public `@bryntum/*` packages are placeholders; trial builds published on public npm as `@bryntum/grid-trial` etc. without authentication. — [@bryntum/grid README on unpkg](https://unpkg.com/@bryntum/grid@7.3.4/README.md); [npm @bryntum/grid](https://www.npmjs.com/package/@bryntum/grid)

### Inferences
- Common implementation pattern (inferred from the documented behaviors): key = base64/hex string encoding `{plan, expiry or maintenanceEnd, orderId, optional app/company}` plus a signature or checksum; the package embeds a build/release date constant at publish time and compares it against the key's maintenance date (perpetual model) or compares `Date.now()` against the key's expiry (subscription/trial). No vendor phones home; none use asymmetric signatures verifiable only server-side because the check must run in the browser, so a leaked valid key always works and the deterrent is contractual plus key text that names the licensee.
- Least hostile converting approach: public npm package; features work without a key; missing/invalid key shows a small watermark plus one console warning (MUI/AG Grid style) rather than a blocking modal (Handsontable style); perpetual-in-production keys tied to release dates so renewals are optional unless upgrading; a free keyword for non-commercial/evaluation (Handsontable's `non-commercial-and-evaluation`, FullCalendar's honor-system keys) so free-tier users are never nagged; and a trial key that simply has a short expiry.
- Public npm vs private registry: private registries (Tiptap Pro, Font Awesome Pro, Bryntum) physically gate the code but create token-leak, CI and lockfile headaches and still rely on contract; they fit "pay to install" products. Key-in-public-package (AG Grid, MUI, Handsontable, amCharts, FullCalendar) fits "free to try, pay to deploy" and is far simpler for a solo seller. Bryntum's split (trial on public npm, licensed on private) is a middle path.
- Trial handling without infrastructure: AG Grid lets users test locally with no key (watermark) and issues trial keys by request; MUI/Handsontable encode expiry in the key. A solo seller can issue time-limited trial keys from the same generator and avoid a trial server.

### Gaps
- Primary amCharts `addLicense` documentation and FullCalendar's runtime check details were not located; both are described from secondary pages.
- No vendor publishes its key format or signing scheme; the "signed string" description is inferred from documented behaviors, not from source inspection.
- No evidence was found of AG Grid or MUI pursuing enforcement against leaked keys; the Aspose and Stimulsoft cases are analogies.
