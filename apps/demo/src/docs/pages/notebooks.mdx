## A notebook reads top to bottom

A notebook is an analysis written as prose, with its charts in line. It's one Markdown file in a [project folder](/docs/project-folders), named `<name>.eda.md`. Text outside the fences is prose. Each fenced `eda` block holds [dashboard text](/docs/dashboard-text), and its charts appear where the block sits, at the full width of the column.

## Try it with the sample notebook

You need [Node.js](https://nodejs.org) 22 or later. In a terminal, in any empty folder:

1. **Copy and open the sample.** Run `npx exploreda --example forecast`. It copies a project of Texas electricity demand into `./exploreda-example-forecast` and opens its notebook, `forecast.eda.md`.
2. **Edit the prose.** Hover the first paragraph, choose **Edit text**, add a sentence, and choose **Done**. That paragraph changes in `forecast.eda.md`, and nothing else does.
3. **Edit a block's text.** Hover the first chart and choose **Edit block**. Change its `title=`, and the chart's title changes as you type. Choose **Done**.
4. **Edit a chart in the page.** Open **Chart settings** on **Actual minus forecast** and set the series' **Line width** to 3. The block gains one line, `series delta lineWidth=3`.
5. **Reopen it.** Stop the server with Ctrl-C and run the command again. The notebook opens with your edits, since they're in the file.

````markdown
# Did Texas demand run off forecast?

ERCOT forecasts each hour's demand a day ahead.

```eda
eda query=demand
time:date=demand.time label=Hour
actual:num=demand.actual
forecast:num=demand.forecast
```

Subtracting the forecast turns the question into one line.

```eda
calc delta = actual - forecast   # positive: demand above forecast
line @delta x=time y=delta title="Actual minus forecast" {
  rule y=0 "On forecast"
}
```

The miss widens after February 15.
````

Open the project with `npx exploreda`, and the notebook is listed under **Notebooks**. Run `npx exploreda --example forecast` for the full forecast notebook.

## Explore real notebook examples

[Daily data viz](/daily) publishes a narrative notebook, composed graphic, or dashboard every day over real datasets. Each piece includes local data, source credit, and findings the tests recompute. Notebook chart selections stay local to their chart; dashboards link their views.

## Set each section beside its charts

A published notebook can read like a figure-led report. Pass `layout="sections"` to `ExplorEdaNotebook`, and once the notebook is at least 960 pixels wide each `##` section puts its text in a column beside its charts. A finding written after a chart stays with its section's text, and the text stays in view while a tall chart or table scrolls past. A chart titled like its section drops the repeated title. Sections with no charts, such as a takeaway and its limits, share a row.

Each chart takes the height its contents need. A row chart or heatmap grows with its categories. Small multiples (`facet.enabled=true facet.type=wrap facet.rowVariable=…`) grow by one row of panels for each row the [facet layout](/docs/facets) makes at the notebook's width, up to about 1,100 pixels, so a facet of a dozen panels shows them all without a pager. In the sections layout, a section that draws small multiples puts its text above them and gives them the notebook's full width, so they get more columns.

Narrower notebooks, and notebooks you can edit with `onTextChange`, keep the single reading column. [Daily data viz](/daily) notebooks use this layout.

## Show the text beside the notebook

`NotebookSourceEditor` with `language="notebook"` edits a whole notebook's text: Markdown, with the dashboard text in each `eda` fence in color. Put it beside an `ExplorEdaNotebook` that gets the same text and `onTextChange`, and each side follows the other. Typing in the text updates the charts once typing pauses, and a chart edit rewrites its line in the text. [Daily data viz](/daily) notebooks do this under **Source**. Edits there stay on the page until it reloads, and **Reset** brings back the published text.

## Explore a copy of a chart

A reader who finds a chart interesting can pull a copy aside and change it without changing the notebook. Pass `onExploreChart` to `ExplorEdaNotebook`, and each chart shows an Explore button in its header. The callback receives the chart's id and the notebook's settings as they are now. `exploreChartCopy(settings, id)` turns them into a workspace that holds the copy at full width, with the notebook's calculations, color scales, and field settings. Pass the workspace already open as a third argument to add the copy under the charts there, so several charts can sit side by side.

Open the workspace in an `ExplorEda` beside the notebook. It has the Fields and Rows drawers, so a reader can sort and search the rows, add charts, and change the copy. `defaultRowsOpen` opens the Rows drawer at once, for a workspace that starts from the rows. On [Daily data viz](/daily), every notebook chart has Explore, and **Explore rows** opens the rows behind the notebook.

## Split a notebook into sheets

A notebook with two or more `#` headings is a book of sheets. Each heading starts a sheet, named by its text, and the sheets show as tabs, read one at a time. The text before the first heading is the lede, shown above the tabs. A notebook with one `#` heading has a title, not sheets, so nothing changes for notebooks already written.

````markdown
**Did Texas demand run off forecast?** ERCOT forecasts each hour a day ahead.

```eda
eda query=demand
calc delta = actual - forecast
```

# Two months

```eda
line @delta x=time y=delta title="Actual minus forecast"
```

# The storm week

```eda
line @storm x=time y=delta where.time=2021-02-14..2021-02-20
```
````

Sheets split the reading, not the analysis: every sheet charts the same rows, and a calculation or alias defined on one sheet works on all of them. Arrow keys move between tabs. A host can set the open sheet with `sheet="the-storm-week"` (a heading as a URL-safe id) and hear a choice through `onSheetChange`, which [Daily data viz](/daily) uses to put the sheet in the address. When a notebook can be edited, each sheet's heading stays in its text, so editing it renames the sheet.

## How blocks work together

- **Definitions reach the whole notebook.** A calculation or field alias in any block applies to every block, in any order. Define `delta` once and chart it anywhere.
- **A block can hold several charts.** They stack in the order you write them. A block with only definitions shows what it defines.
- **The data comes from the project.** `eda query=demand` picks the query every block charts. Without one, the notebook charts the project's first query.
- **Clicks and brushes stay with their chart.** Selecting a range in one chart doesn't narrow the others, so a zoomed window can sit below the full series. A `filter` line still narrows every chart.

## Live findings

A finding is a named value that follows one chart's selection. Declare it on a `finding` line in any `eda` block, then write `{{name}}` in the prose where the value goes. Select bars in the chart it names, and the sentence changes with them. A link to `#finding:name` opens the exact rows behind the value.

````markdown
Selected **{{n}}** of {{eligible}} active reviews. Their average score is {{mean-score}}; [show records](#finding:mean-score).

```eda
field score as=numeric
finding @n count chart=@regions
finding @eligible count chart=@regions population=eligible
finding @mean-score average score chart=@regions digits=2
row region @regions where.active=true
```
````

A `finding` line has a name, a summary, and a field to measure unless it counts:

- **Summary:** `count`, `sum`, `average` (or `avg`), `min`, or `max`, the same summaries a metric card offers. A count of no rows is 0.
- **`chart=@name`** names the chart to follow. The finding reads the rows that chart can show, after its own `where.` filters and any `filter` line, then keeps the ones its selection keeps. A cleared selection keeps them all. Other charts' selections never change it. Without `chart=`, the finding reads every row of the data, whatever any chart or filter selects.
- **`population=eligible`** ignores the chart's selection but keeps its filters, so a finding can name the total a selection is part of.
- **`where.field=value`** narrows the finding further, with the same values, ranges, and text tests as a chart's `where.`.
- **`digits=2`** fixes the decimal places. Without it, the value uses the field's own format.

The value and its records always come from the same rows. Records list each row the summary read and say why a row was left out, such as a missing value or text in a number field. A selection that changes those rows closes the records rather than showing rows from before.

When a finding has no value, the prose says why in place of a number: no rows, no valid values, not a finite number, or an unknown finding when the text names one it never declares. A broken `finding` line is reported at its line, as any block problem is. `{{name}}` stays as written inside code, after a backslash (`\{{name}}`), and in a link's address.

## Compare two findings

A comparison names two findings and reads their unrounded values from the same moment, so both sides always describe the same selection. There are two kinds:

- **`finding @gap difference a-mean b-mean`** subtracts the second from the first and shows the sign: −8.75 for all active reviews, +15.00 once East is selected. Both sides must summarize the same field the same way, from the same chart; only their `where.` filters may differ. Without `digits=`, it takes the first side's.
- **`finding @east-share share n eligible`** shows the first count as a percent of the second. The whole must hold the part: count it from the same chart with `population=eligible`, or from every row with no `chart=`. East's four rows are 40% of ten active reviews and 33.3% of all twelve. A part of no rows is 0%; a whole of no rows has no share.

```eda
finding @a-mean average score chart=@regions where.group=A digits=2
finding @b-mean average score chart=@regions where.group=B digits=2
finding @gap difference a-mean b-mean
finding @all count
finding @all-share share n all digits=1
```

The records for a comparison show its calculation, then each side's rows on their own. When either side has no value, the comparison says why in its place. Write the sentence around a comparison so it holds for any selection, such as `a difference of {{gap}}`. A number that changes can contradict a conclusion written around one value.

## Edit the text or the charts

Both edits change the same file, and the notebook updates as you go.

- **In the app.** Hover a block and choose **Edit block** to change its text, with charts updating as you type. Choose **Edit text** on prose to change its Markdown.
- **Through a chart.** Change a chart in its settings, axes, or filters, and the notebook text changes to match. Only the changed setting is rewritten, so comments, spacing, and your field names stay as you wrote them. A new chart type rewrites that one chart's line.
- **In your editor.** Save the file in any editor and the open page reloads it.

When a block's text has a problem, the block says what it is and on which line. Its charts keep showing the last version that worked until the text is fixed. A chart change that can't be written as text is undone, with a note saying why.

## Check a notebook from the command line

```bash
npx exploreda-dsl check forecast.eda.md
```

`check` reads the notebook's project data and lists each problem with its line and a suggested fix. Add `--data rows.csv` to check against a data file instead. `exploreda-dsl fmt forecast.eda.md --write` tidies the text inside `eda` blocks and leaves the prose alone.
