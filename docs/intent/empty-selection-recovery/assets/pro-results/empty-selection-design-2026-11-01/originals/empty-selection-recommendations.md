# Recommendation dispositions: build exact, explicit recovery

**Recommended build:** add **Recover rows**, a detached comparison of removing one reviewed restriction, with exact returned records and an explicit Apply action. Extend it to Rows/table and chart-local populations, then bounded pairs and supported notebook/folder flows. Preserve the rest of the investigation and the option to keep an empty result.

**Baseline:** explorEDA `d3920a285f3755a8324998775deb131747e959f5`. **Date:** November 1, 2026. **Mode:** Design. These are decisions for implementation, not claims that the proposed feature exists. The full rationale is in the [design report](empty-selection-design-report.md); actual files, tests, documentation, runnable examples, risks, and three-width acceptance flows are in the [implementation plan](empty-selection-implementation-plan.md).

## Disposition meanings

| Disposition | Meaning | Revisit rule |
| --- | --- | --- |
| **Build** | Included in the recommended bounded capability and assigned to a milestone. | Change only when concrete integration evidence contradicts a stated assumption. |
| **Explore** | A specific improvement whose value or technical fit should be measured after the useful capability exists. | Use the named technical evidence; no outside-user demand gate is implied. |
| **Defer** | Useful or conceivable scope deliberately excluded from this build. | Revisit as a separate bounded feature, preserving the current contract. |
| **Avoid** | An approach that breaks semantics, clarity, or the stated architecture. | Do not use as an implementation shortcut. |

Stable IDs below identify the decisions even if their wording evolves. Fixture IDs use the separate `ESR-F##` namespace. Milestones are M1 workspace singles, M2 Rows/table, M3 chart populations, M4 pairs, and M5 notebook/folder integration.

## Build

| ID / delivery | Recommendation | Reason and acceptance evidence |

| **ESR-001 · Build · M1** | Ship exact single-removal comparison as the main recovery action. | It answers a useful new analytical question with a small, reviewable change. F01 previews A/B after removing chart East and C/D after removing Workspace West; neither changes the live investigation until Apply. |
| **ESR-002 · Build · M1–M5** | Name one population beside every count and result. | Workspace intersection, self-excluded chart context, selected chart rows, Rows, table search, and notebook findings have different source contracts. F01, F08/F09, F24, and F26 distinguish them. No unqualified “rows recovered” count. |
| **ESR-003 · Build · M1** | Address one stored Filter occurrence by owner, array, original position, and revision. F02/F17/F27/F28 prove these distinctions. Ambiguous duplicate workspace-field entries require review instead of silent normalization. |
| **ESR-004 · Build · M1/M4** | Recompile the complete changed chart owner and verify that its old membership is contained in its new membership over all source IDs. | The real bar compiler can ignore a clause or expose an older range. A removal may exchange rows. F18/F19/F25 distinguish this from a true relaxation; F29 proves a pair can be valid even when one constituent single is not. Do not prune that pair. |
| **ESR-005 · Build · M1** | Evaluate on a detached snapshot of current effective columns, source IDs, settings, and target state. | Current field conversions and calculated values determine membership. Capture once, seal the getter, check the revision around capture, and use real helpers/definitions. F03–F05/F11/F12/F20/F22/F23 cover date, missing, numeric, specification, and derived semantics. Preview never calls live filter setters. |
| **ESR-006 · Build · M1** | Show exact returned records with a whole-population count and an explicit display limit. | Records let the analyst judge what relaxing a condition means. A “first 100 of N” view must not turn N into a sample estimate. The detached pane must not reapply the unchanged live search and hide its own candidate rows. Source-position IDs expire with the data epoch. |
| **ESR-007 · Build · M1** | Add a transient recovery revision, explicit stale state, held-edit guard, and final synchronous Apply check. | Provider nonce alone does not cover all local search/settings changes. Data, calculations, field conversion, specification limits, source text, restoration, edit holds, and editability can invalidate the preview. Never finish someone’s draft or refresh expensive work automatically. |
| **ESR-008 · Build · M1** | Apply all reviewed removals through one prepared provider command and one coherent publication. | Suppressing callbacks is not store atomicity. Prepare arrays and predicates first; handle wrapper failure without publishing partial state. Test visible memberships, settings, and one host callback. Preserve every unreviewed owner, sibling, search, calculation, axis, bin, limit, and layout property. |
| **ESR-009 · Build · M1/M5** | Preserve chronological demo Undo/Redo and provide a separately named, guarded “Restore removed restrictions” edit. | History navigation and a compensating inverse have different effects. An inverse creates a new edit/checkpoint, expires on any later meaningful saved-state edit or data/source restoration, and restores only reviewed properties while its exact post-Apply revision is current. No full-snapshot overwrite. |
| **ESR-010 · Build · M1/M5** | Preserve typed runtime/history values and state the existing durable JSON boundary explicitly. | The demo’s JSON clone loses undefined and nonfinite filter values. Replace its internal checkpoint clone/equality with value-preserving behavior. Keep the public saved shape: validated JSON rejects NaN/infinite filter datums; undefined-to-null and negative-zero-to-zero normalization is membership-equivalent but not byte-exact. Raw-row special tags do not encode filter settings. Test these separately. |
| **ESR-011 · Build · M1 onward** | Make the recovery surface usable at 1280, 783, and 390px, with focus return, accessible status, bounded scrolling, and visible actions. | Width does not grant or revoke edit permission. Apply follows actual readOnly/host state. The three downloadable F01 mockups establish the intended layout; real pointer and keyboard flows remain implementation acceptance. This does not promise all existing charts work on mobile. |
| **ESR-012 · Build · M2** | Add Rows-local filters/search and table-local search with their actual ownership and matching rules. | A local search can be empty while the workspace contains records. Search is case-insensitive but untrimmed and includes hidden/current calculated fields. F06–F08/F24 prove returned IDs and prevent a local result from being mistaken for a linked-filter conflict. |
| **ESR-013 · Build · M3** | Add chart context/selection/local-population recovery and typed empty-state diagnosis. | Source rows, plottable values, visible marks, and setup validity are different. F09/F11/F15/F16/F27 establish local/specification and no-marks boundaries. Removing specification status keeps limits; removing a bin keeps status and bins. Do not promise a mark count from a record count. |
| **ESR-014 · Build · M4** | Evaluate pairs among at most 12 explicitly selected, unkept units; show exact coverage and temporary Keep choices. | F10 has no useful single but four useful pairs. At most 66 pairs is bounded and inspectable. Keep changes invalidate prior coverage. F21 proves a triple can succeed after every tested single/pair fails; say “no tested single or pair,” never “no solution.” A successful pair is minimum cardinality only when every admitted single failed on an empty target. |
| **ESR-015 · Build · M5** | Integrate notebook and folder recovery through their actual persistence owners. | Transient notebook selections stay session-local and do not write text. Authored chart-local removals need complete writeback/compile preflight, stable named-chart identity, and preservation of unrelated runtime selections; otherwise offer Edit source. Folder dashboard saving checks exporter omissions and compiles text before queue/write. On failure, preserve accepted runtime settings and last good disk and report unsaved state. No new precommit host API. F13/F26 supply exact populations. |
| **ESR-016 · Build · Every milestone** | Ship each vertical slice with focused behavior tests, a docs section, and a runnable example. | The mission asks for a useful capability, not an audit or research prerequisite. The plan names actual source paths and proposed new modules. Port the separately authored exact expectations, then test real Cancel, Apply, stale state, host history, and persistence; the standalone companion does not substitute for those integrations. |

## Explore

| ID / timing | Recommendation | Evidence that would justify it |
| --- | --- | --- |
| **ESR-017 · Explore · after measured M1/M4 use** | Move expensive scans to a worker only if cooperative chunks still cause measured interaction stalls. | First measure source size, predicate cost, latency, retained masks, and cancellation. A worker requires a deliberate transport for effective values and supported predicates; registered closures are not automatically transferable. No additional formula runtime. |
| **ESR-018 · Explore · optional optimization** | Use Crossfilter ignore-dimension APIs for whole-owner counts where parity and lack of side effects are proven. | An ignored dimension drops the whole owner, so it cannot generally answer a one-occurrence removal. Require exact fixture/live parity and a measured benefit for the applicable subset. Keep the detached evaluator as semantic authority. |
| **ESR-019 · Explore · after M3** | Qualify more chart modes/custom definitions and renderer eligibility explanations. | Add a mode only after its pure predicate, required-field behavior, and record-versus-mark distinction are demonstrated. Workspace recovery can remain useful without promising exact mark restoration for every facet, aggregate, map viewport, or custom renderer. |
| **ESR-020 · Explore · after correctness is established** | Refine snapshot invalidation, mask storage, and record paging reuse. | Conservative invalidation and bounded owner-mask caches are the default. Reuse more state only with a proven dependency boundary and a measured benefit. Keep the reviewable reference evaluator; do not introduce a generic dependency graph. |

These items do not block Build. The quantitative defaults in the report—64 MiB mask budget and approximately 4–8ms work chunks—are starting proposals for measurement, not benchmark results or a service-level promise.

## Defer

| ID | Recommendation | Reason and bounded route back |
| --- | --- | --- |
| **ESR-021 · Defer** | Automatically widen numeric/date intervals, replace categories, infer a nearest record, or relax joins/SQL. | These actions need a cost/preference model and can change the analyst’s question. The current unit is removal of a whole stored restriction. Keep explicit Edit range/condition and host query/source navigation; define any nearest-match feature separately. |
| **ESR-022 · Defer** | Automatic search beyond pairs, minimal unsatisfiable cores, or a complete relaxation lattice. | The combination space grows rapidly and a complete explanation need not identify the analyst’s preferred change. F21 makes the limit explicit. A future user-selected three-unit comparison could be a bounded extension; it must not silently become exhaustive search. |
| **ESR-023 · Defer** | Direct authored notebook workspace/finding edits, comparison-denominator changes, and mixed transient/authored pairs. | The current writer handles chart text and omits these domains or cannot guarantee the combined transaction. Show exact supported counterfactuals and Edit source; a future authoring slice must prove complete writeback and preservation of unrelated selections. Do not claim empty writer results mean success. |
| **ESR-024 · Defer** | Public solver APIs, persisted recovery preferences/provenance, general host history, and a new filter-setting serialization schema. | Existing public props and callbacks suffice for the built-in capability. Transient Keep, counts, IDs, receipts, and failed attempts should not enter saved state. A future public contract or special-value durable codec needs its own concrete requirement and compatibility decision. |

## Avoid

| ID | Rejected approach | Reason |
| --- | --- | --- |
| **ESR-025 · Avoid** | Temporarily clear/set live Crossfilter filters during Preview and restore them afterward. | Intermediate memberships, callbacks, charts, calculations, or history can observe the speculative state; cancellation and exceptions complicate restoration. Use a detached evaluator. An isolated replacement prepared for an actual Apply transaction is a different operation. |
| **ESR-026 · Avoid** | Silent filter clearing, default Clear all, automatic largest-count choice, or blaming the latest restriction. | An empty result can be intentional, larger counts do not express preference, and imported restrictions may have no trustworthy action history. Preserve all state until the user reviews and applies a named change. |
| **ESR-027 · Avoid** | AND every stored chart clause, count a whole owner as one occurrence, inventory only visible chips, or clone typed predicates through ordinary JSON. | Each shortcut is contradicted by the baseline semantics. Full-owner compilation, occurrence identity, hidden-effective-clause inventory, and value-preserving snapshots are essential; F17–F19/F25/F27–F29 expose failures. |
| **ESR-028 · Avoid** | Conflate workspace rows, self-excluded context, table hits, plotted marks, setup state, or historical counts. | A plausible count for the wrong target is an incorrect answer. Label the scope, reconcile the current baseline, and keep source-data refresh distinct from history restoration. Do not silently remove an unmodeled predicate to make a count computable. |
| **ESR-029 · Avoid** | Permanent candidate recomputation, silent candidate truncation, sampled totals labeled exact, or claiming no solution after a bounded search. | These create unnecessary cost or overstate evidence. Compute on demand, cancel superseded work, disclose the admitted unit set/coverage, and publish exact counts only after each candidate finishes. |
| **ESR-030 · Avoid** | Make outside-user demand, an ownership audit, broad filtering cleanup, or an unbuilt research platform a prerequisite. | This mission and `docs/research/DIRECTION.md` supersede R052’s old demand gates. Build the bounded capability directly. Fix only concrete integration issues required by its semantics, such as typed history cloning and atomic Apply. |

## Primary-source basis for the selected model

These are primary mechanisms and research arguments, not claims that another product implements this exact design. The report compares them in detail.

- **Context and ownership:** [Crossfilter maintainer explanation](https://github.com/square/crossfilter/issues/161), [Crossfilter releases](https://github.com/crossfilter/crossfilter/releases), and [Mosaic selection documentation](https://idl.uw.edu/mosaic/api/core/selection.html) support keeping contextual populations and owner-specific selection semantics explicit. They inform ESR-002/004/018/025.
- **Analyst intent and history:** [Qlik associative states](https://help.qlik.com/en-US/sense/May2026/Subsystems/Hub/Content/Sense_Hub/Selections/associative-selection-model.htm) distinguish selected intent from possibility; [Qlik back/forward selection history](https://help.qlik.com/en-US/sense/May2026/Subsystems/Hub/Content/Sense_Hub/Selections/SelectionsToolbar/step-back-forward-selections.htm) is a separate operation. They inform ESR-001/009/026.
- **Scope and refresh cost:** [Tableau filtering](https://help.tableau.com/current/pro/desktop/en-us/filtering.htm), its [performance checklist](https://help.tableau.com/current/pro/desktop/en-us/perf_checklist.htm), [Power BI filter scopes](https://learn.microsoft.com/en-us/power-bi/explore-reports/end-user-report-filter), and [Elasticsearch post-filtered hits](https://www.elastic.co/docs/reference/elasticsearch/rest-apis/filter-search-results) inform ESR-002/012/029. [Power BI blank-measure behavior](https://learn.microsoft.com/power-bi/create-reports/desktop-show-items-no-data) informs ESR-013/028.
- **Explanation versus preference:** [Chapman and Jagadish, Why Not?](https://dbgroup.eecs.umich.edu/files/ChapmanSIGMOD09.pdf), [Koudas et al., Relaxing Join and Selection Queries](https://www.vldb.org/conf/2006/p199-koudas.pdf), and [Mottin et al., The New Frontier of Empty Answer Problem](https://www.vldb.org/pvldb/vol6/p1762-mottin.pdf) inform explicit record evidence, temporary Keep choices, and the bounded scope of ESR-014/021/022. The ranking and exact limits here are original design choices.

## Delivery acceptance and evidence limits

The standalone [verification result](empty-selection-verification.json) reports **29 scenarios, 72 preview alternatives, and 422 passing assertions**. Its source helper/selected compiler bodies are from the exact baseline; its expected record memberships were authored separately. [Fixture data](empty-selection-fixtures.json), the [fixture guide](empty-selection-fixtures.md), and the [runnable verifier](verify-empty-selection-fixtures.mjs) preserve that evidence.

That result does **not** prove live Crossfilter parity, React behavior, provider atomicity, actual Cancel, host Undo, notebook writeback, file persistence, or browser usability. Those are the concrete acceptance tasks in the implementation plan. The [1280px](recovery-preview-1280.svg), [783px](recovery-preview-783.svg), and [390px](recovery-preview-390.svg) SVGs were rendered and inspected as static design assets.

**Access:** the complete 37-file source packet was read first; decisive supplemental source was inspected at the same pinned baseline. No implementation commit or product deployment was made. The report lists every supplied file and the scope of supplemental reads.

**Open integration choices:** use a conservative revision before selective reuse; admit additional chart modes through parity tests; prefer a detached record pane; use one safe prepared Apply transaction; and preflight the authored notebook subset. These choices have defaults and do not require new demand or user confirmation.
