## Selection and row scope

Category-count bars use rows that remain after other filters and the current facet. Clicking a category filters linked views. Numeric bins use that same live row set; clicking a bin or dragging across bins filters to their snapped numeric range. Each bin leaves out its upper edge, except the last, so a value on an edge counts in the bin to its right. A selected range keeps that rule: it selects exactly the rows its bars count, and its filter reads like `Weight: 0 to < 0.5` when the range ends before the last bin. Whole-number bins have edges halfway between values, so their filters keep reading like `Delivery days: 1.5–4.5`. The count and bin domains use all source rows, which keeps categories and scale positions stable.

<Callout title="Grouped summaries read a different scope.">
  A named grouped summary calculates from globally filtered rows. When chart
  filters or facets are active, its row scope can differ from category counts.
</Callout>

## Settings and limits

Set the grouping field, choose category counts or numeric bins, and adjust the bin count. For a grouped summary, choose a group field, an operation, and—when needed—a numeric measure.

- **Order** keeps category bars in data order, sorts them A to Z (`categoryOrder=label`), or puts the largest first (`categoryOrder=value`). Category counts, grouped summaries, and series bars all follow it. The value order comes from all source rows, so bars keep their places as other charts filter; series bars sort by their category total. Numeric bins keep their numeric order.
- Missing or non-finite measurements do not enter numeric bins.
- Alt-click a bar or use the chart trace action to inspect how it was computed.

## Authored boundaries

Auto bins come from the data, so their edges move when rows change. To keep the same intervals from one refresh to the next, set **Edges** to **Width** in the **Bins** section. Each edge is `origin + index × width`, so a width of 0.01 and an origin of 0 puts edges at 11.94, 11.95, and so on.

- **Width** and **Origin** change the grid and keep the range of bin positions.
- **Range** sets the first and last edge. A typed edge moves outward to the nearest grid edge.
- **Fit** sets the range to the smallest run of bins that covers every source value, with at least one bin.
- A grid holds 1 to 512 bins. Edges that would collapse at a large magnitude are rejected.

In dashboard text, the grid reads `bins.mode=width bins.width=0.01 bins.origin=0 bins.first=1194 bins.last=1208`.

## Coverage and exact edges

Each bin keeps its lower edge and leaves out its upper edge. Only the last bin keeps both edges. A value past the first or last edge counts in a **coverage tail**: a dashed bar outside the range. The tails use strict comparisons, so a value equal to the last edge is in the last bin, not in the upper tail.

Edges are built from the decimal text of the width and origin, and each edge converts to a number once. Measurements are compared with the edges exactly. No measurement is rounded, so 0.30000000000000004 is above an edge at 0.3.

The status line shows **n**, the finite measurements in scope with the tails included. Missing values and values that are not numbers are counted separately and enter no bin.

## Saved selections

A click on a bin selects its exact interval, such as `Diameter (mm): 12.05 to < 12.06`. A click on a tail selects a strict range, such as `> 12.08`. Click the same bar again to clear it. A drag selects the bins it crosses.

With saved edges, a selection keeps the range it was made with. When the data or the edges change, the range does not move. A bin that the range covers in part shows its selected rows solid over a faded bar, and the readout and trace give both counts. In dashboard text, a strict end uses interval brackets: `select."Diameter (mm)"=[12.05..12.06)` and `select."Diameter (mm)"=(12.08..)`. A range without brackets, such as `0..2`, includes both ends.

## Annotations

The **Notes** tab adds lines and bands on the value axis, such as a goal. A **callout** attaches to a bar by its **Category**: a bar sums many rows, so it never stands for one record. Series bars group their marks, so they take lines and bands only.

On a histogram the x axis is the binned field, so `rule x=mean`, `median`, `min`, and `max` compute from that field's values in the rows the chart draws. `rule x=mean population=all` reads every row instead of the filtered ones.
