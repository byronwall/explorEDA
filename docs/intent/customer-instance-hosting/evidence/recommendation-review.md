## Independent provider and cost checks

- Cloud Run's current security documentation describes second-generation instances as using two sandbox layers, including a VM-equivalent boundary. Its security page describes instances as stateless; a restart or replacement does not preserve local files as authoritative state. Billing docs say health probes require instance-based billing. HTTP/1.1 client disconnects are not propagated to the container, so SQL cancellation needs driver and transport proof. The service max can overshoot; include rollout and tagged revisions in later connection budgets. [Cloud Run security](https://docs.cloud.google.com/run/docs/securing/security), [billing settings](https://docs.cloud.google.com/run/docs/configuring/billing-settings), [maximum instances](https://docs.cloud.google.com/run/docs/configuring/max-instances), [client disconnect troubleshooting](https://docs.cloud.google.com/run/docs/troubleshooting#client_disconnect).
- Cloudflare's current docs show Containers is generally available, bills memory/disk by provisioned time and CPU by active use, and requires adding Worker and Durable Object charges. The outbound policy applies to HTTP(S) 80/443; other ports bypass it when internet remains enabled, and are denied when internet is disabled. Current custom instance shapes require at least 3 GiB RAM per vCPU. Do not treat this feature as a fixed PostgreSQL egress identity or generic non-HTTP firewall. [Containers GA](https://developers.cloudflare.com/changelog/post/2026-04-13-containers-sandbox-ga/), [Containers pricing](https://developers.cloudflare.com/containers/platform/pricing/), [instance limits](https://developers.cloudflare.com/containers/platform/limits/), [outbound traffic](https://developers.cloudflare.com/containers/configuration/outbound-traffic/).
- Render documents environment-level isolation for private network traffic. Public `onrender.com` endpoints remain reachable, and active connections survive the isolation toggle until restart. The 1 CPU/2 GB service shape matches the cited 1c-2g SKU; Pro costs $25/month before per-service compute. This is a useful conditional alternative, not a universal cost winner. [Render projects and environments](https://render.com/docs/projects), [compute plans](https://render.com/docs/compute-plans), [pricing](https://render.com/pricing).
- Cost rows in the raw packet are modeled from list rates and synthetic duty cycles. They exclude variable customer support and several optional network, source-database, transfer, identity, and incident costs. The 1-vCPU/2-GiB Cloud Run instance-billed arithmetic is $0.000022/second × 2,592,000 seconds = $57.024 per 720-hour full-occupancy month before egress and shared costs; this is a gross scenario, not a quote or budget. Render's modeled $25/service plus $25 Pro workspace and bandwidth assumes published plan prices and usage rules. Actual provider billing, allowances, region, account credits, idle tails, and workload are unmeasured. No precise fleet total is accepted as a customer price.

## Gaps before a provider decision

The first three initiatives still own query semantics, driver capabilities, and result transport. Their source-snapshot, types, identity, completion, and cancellation contracts must align before hosting can claim a bounded complete result. No customer database, region, monthly usage shape, budget, cold-start target, availability promise, or contractual isolation tier is selected. Confirm the service-level isolation promise and any mandatory first-customer network profile before selecting a provider for a hosted proof.
