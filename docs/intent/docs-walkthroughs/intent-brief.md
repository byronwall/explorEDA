# Docs walkthroughs for files and React

## My read

The landing and docs entry work shipped run-through walkthroughs for local folders, databases, notebooks, and the team server (see the [feature inventory](../../application-feature-inventory.md#initiatives-retired-2026-10-23)). Two entry paths from the same review never got a lesson, and a few docs fixes were left as unchecked ideas.

## What matters most

- **A file lesson.** Open a file, build a chart, save, and reopen, using the existing shop sample.
- **A React persistence lesson.** Embed the workspace, save its state, and restore it, without duplicating the package README.
- **Runtime orientation.** A short section or page that says where each mode runs and what it stores: browser, CLI, team server, React host.
- **Search words.** Test what people search for before changing metadata.

## Boundaries

- Each walkthrough is run step by step before it merges, as the earlier four were.
- Keep the MDX system, existing URLs, the chart chooser, and the order-book example.
- No proof-screenshot strip or new media system, and no sidebar restructure without a reader-need reason.

## What seems settled

The local-folder, database, notebook, and team-server walkthroughs are done and stay as they are. The order-book example stays unless a small comprehension test finds a better one.

## Next step after confirmation

Write and run the file lesson first. It is the shortest path and the most common entry.
