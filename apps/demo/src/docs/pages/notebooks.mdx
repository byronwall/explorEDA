## A notebook reads top to bottom

A notebook is an analysis written as prose, with its charts in line. It's one Markdown file in a [project folder](/docs/project-folders), named `<name>.eda.md`. Text outside the fences is prose. Each fenced `eda` block holds [dashboard text](/docs/dashboard-text), and its charts appear where the block sits, at the full width of the column.

## Try it with the sample notebook

You need [Node.js](https://nodejs.org) 22 or later. In a terminal, in any empty folder:

1. **Copy and open the sample.** Run `npx exploreda --example forecast`. It copies a project of Texas electricity demand into `./exploreda-example-forecast` and opens its notebook, `forecast.eda.md`.
2. **Edit the prose.** Hover the first paragraph, choose **Edit text**, add a sentence, and choose **Done**. That paragraph changes in `forecast.eda.md`, and nothing else does.
3. **Edit a block's text.** Hover the first chart and choose **Edit block**. Change its `title=`, and the chart's title changes as you type. Choose **Done**.
4. **Edit a chart in the page.** Open **Chart settings** on **Actual minus forecast** and set the series' **Line width** to 3. The block gains one line, `series delta lineWidth=3`.
5. **Reopen it.** Stop the server with Ctrl-C and run the command again. The notebook opens with your edits, since they're in the file.

````markdown
# Did Texas demand run off forecast?

ERCOT forecasts each hour's demand a day ahead.

```eda
eda query=demand
time:date=demand.time label=Hour
actual:num=demand.actual
forecast:num=demand.forecast
```

Subtracting the forecast turns the question into one line.

```eda
calc delta = actual - forecast   # positive: demand above forecast
line @delta x=time y=delta title="Actual minus forecast" {
  rule y=0 "On forecast"
}
```

The miss widens after February 15.
````

Open the project with `npx exploreda`, and the notebook is listed under **Notebooks**. Run `npx exploreda --example forecast` for the full forecast notebook.

## Explore real notebook examples

[Daily data viz](/daily) publishes a narrative notebook, composed graphic, or dashboard every day over real datasets. Each piece includes local data, source credit, and findings the tests recompute. Notebook chart selections stay local to their chart; dashboards link their views.

## Set each section beside its charts

A published notebook can read like a figure-led report. Pass `layout="sections"` to `ExplorEdaNotebook`, and once the notebook is at least 960 pixels wide each `##` section puts its text in a column beside its charts. A finding written after a chart stays with its section's text, and the text stays in view while a tall chart or table scrolls past. A chart titled like its section drops the repeated title. Sections with no charts, such as a takeaway and its limits, share a row.

Narrower notebooks, and notebooks you can edit with `onTextChange`, keep the single reading column. [Daily data viz](/daily) notebooks use this layout.

## Split a notebook into sheets

A notebook with two or more `#` headings is a book of sheets. Each heading starts a sheet, named by its text, and the sheets show as tabs, read one at a time. The text before the first heading is the lede, shown above the tabs. A notebook with one `#` heading has a title, not sheets, so nothing changes for notebooks already written.

````markdown
**Did Texas demand run off forecast?** ERCOT forecasts each hour a day ahead.

```eda
eda query=demand
calc delta = actual - forecast
```

# Two months

```eda
line @delta x=time y=delta title="Actual minus forecast"
```

# The storm week

```eda
line @storm x=time y=delta where.time=2021-02-14..2021-02-20
```
````

Sheets split the reading, not the analysis: every sheet charts the same rows, and a calculation or alias defined on one sheet works on all of them. Arrow keys move between tabs. A host can set the open sheet with `sheet="the-storm-week"` (a heading as a URL-safe id) and hear a choice through `onSheetChange`, which [Daily data viz](/daily) uses to put the sheet in the address. When a notebook can be edited, each sheet's heading stays in its text, so editing it renames the sheet.

## How blocks work together

- **Definitions reach the whole notebook.** A calculation or field alias in any block applies to every block, in any order. Define `delta` once and chart it anywhere.
- **A block can hold several charts.** They stack in the order you write them. A block with only definitions shows what it defines.
- **The data comes from the project.** `eda query=demand` picks the query every block charts. Without one, the notebook charts the project's first query.
- **Clicks and brushes stay with their chart.** Selecting a range in one chart doesn't narrow the others, so a zoomed window can sit below the full series. A `filter` line still narrows every chart.

## Edit the text or the charts

Both edits change the same file, and the notebook updates as you go.

- **In the app.** Hover a block and choose **Edit block** to change its text, with charts updating as you type. Choose **Edit text** on prose to change its Markdown.
- **Through a chart.** Change a chart in its settings, axes, or filters, and the notebook text changes to match. Only the changed setting is rewritten, so comments, spacing, and your field names stay as you wrote them. A new chart type rewrites that one chart's line.
- **In your editor.** Save the file in any editor and the open page reloads it.

When a block's text has a problem, the block says what it is and on which line. Its charts keep showing the last version that worked until the text is fixed. A chart change that can't be written as text is undone, with a note saying why.

## Check a notebook from the command line

```bash
npx exploreda-dsl check forecast.eda.md
```

`check` reads the notebook's project data and lists each problem with its line and a suggested fix. Add `--data rows.csv` to check against a data file instead. `exploreda-dsl fmt forecast.eda.md --write` tidies the text inside `eda` blocks and leaves the prose alone.
