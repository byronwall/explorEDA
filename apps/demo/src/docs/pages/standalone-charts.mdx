## Quick start

Use `Chart` from `exploreda/chart` when you want explorEDA's charts in your own React layout, without the workspace. Give it rows and a config, and it draws one chart. There is no toolbar, no grid, and no filtering between charts.

```bash
pnpm add exploreda
```

<StandaloneSideBySide />

Each `Chart` is independent. Put as many on a page as you need, in any layout.

## The config

A config is the chart's `type` plus the settings that differ from that type's defaults. Every setting you leave out takes the same default as a new chart in the workspace.

```tsx
<Chart data={rows} config={{ type: "bar", field: "Region" }} />
<Chart data={rows} config={{ type: "line", xField: "Date", seriesField: ["Units"] }} />
<Chart
  data={rows}
  config={{ type: "scatter", xField: "Price", yField: "Rating", colorField: "Region" }}
/>
```

Setting names are the names the workspace saves. Each chart's page lists every setting of that type, with its default, under **Saved settings**. For example, see [Bar chart](/docs/bar#saved-settings) and [Scatter plot](/docs/scatter#saved-settings). The gallery at the end of this page links each chart type to its list.

- `ChartConfig` is typed per chart type, so your editor completes the settings of the `type` you set.
- A `colorField` is enough to color a chart. `Chart` picks the color scale that the workspace would pick.
- A config that is missing a setting the type needs, such as a scatter plot without `yField`, shows the chart's own empty message.

### Dashboard text

`config` also takes one chart's [Dashboard text](/docs/dashboard-text): the same line that builds that chart in a dashboard.

<StandaloneText />

- A line can use what Dashboard text offers, such as `sum(Units)` or a calculated field, and the chart keeps it.
- A line that builds no chart shows the compiler's message in place of the chart.
- After an edit, `onConfigChange` gives the object form. Store that, or keep the text and leave editing off.

## What a reader can do

- **Hover:** tooltips and hover readouts work as in the workspace.
- **Click and brush:** nothing is selected. A standalone chart has no filter state.
- **Edit:** only when you pass `onConfigChange`.

## Edit settings at runtime

Pass `onConfigChange` to let readers change a chart's settings. The chart shows a settings button that opens the same settings the workspace uses. Each edit calls `onConfigChange` with the new config in its short form: the type, its main field, and only the settings that differ from the defaults.

The chart is controlled, like a React `<input value>`: an edit shows only once you pass the new config back as `config`. Keep the config in state, and the chart and your state never disagree. Leave `onConfigChange` out, and the chart is read-only.

To put the settings somewhere else, such as a sidebar, place a `ChartSettings` with the same `data` and `config`, and pass its `onConfigChange` result to both. Pass `settingsButton={false}` to hide the chart's own button.

<StandaloneEditable />

Try the gear on the chart, or the panel beside it: both edit the same state. The panel offers only the five fields listed in `fields`.

- The short config draws exactly the same chart, so store it as it is.
- A color scale picked for a `colorField` is not part of the config. The chart picks the workspace's default scale again each time.
- Settings that need the workspace, such as filters and calculated fields, have no effect on a standalone chart.

## Styles

Import `exploreda/dist/chart.css` once. It styles only the charts:

- It has no global reset. Your page's buttons, headings, and fonts stay as they are.
- Its theme variables, such as `--background` and `--primary`, sit on each chart's element, not on `:root`. A host that uses the same names keeps its own values.
- Your page's element rules, such as a page-wide `button {}` style, do not restyle the chart's own controls.
- Text in a chart takes your page's font, as the workspace does.
- Tooltips, menus, and popovers mount inside the chart's element, so the same styles reach them.

<Callout type="note" title="Workspace and charts on one page">
  A page that also shows the full `ExplorEda` workspace already loads
  `exploreda/dist/ExplorEda.css`. That file styles standalone charts too, so the
  page does not need `chart.css`.
</Callout>

## Size

- Pass `width` and `height` to set the size in pixels.
- Leave them out to fill the parent element. Give the parent a height, or the chart takes 300 px.
- `height` includes the title line. Pass `title={false}` to give all of it to the plot.
