# Columnar transport recommendation review

This review assigns a disposition to every recommendation in the raw JSON. “Adopt” means the shaping contract accepts the recommendation. It does not mean that an encoding or capacity threshold is already proven for release.

## Evidence anchors

- User intent: [database-backed analysis notes](../../../research/database-backed-analysis-2026-10-11/source-notes.md) and [customer-instance update](../../../research/database-backed-analysis-2026-10-11/customer-instance-update.md).
- Raw technical analysis: [research report](../raw/2026-10-11-pro/columnar-data-transport-research.md), especially §§3–10 and 12; [recommendation JSON](../raw/2026-10-11-pro/columnar-data-transport-recommendations.json).
- Current checkout: `AnalysisProject.ts` defines a scalar row model; `ExplorEdaProject.tsx` evaluates source tables then maps result rows into row objects; `DataLayerProvider.tsx` rebuilds provider structures and caches row-keyed field maps; `CrossfilterWrapper.ts` gives chart and workspace filters distinct populations; `evaluateProject.ts` uses array-object revisions and retains stages and contributor data; chart planners create additional row-level state.
- Primary external checks: [Arrow JS RecordBatchReader v21.2.0](https://arrow.apache.org/js/current/classes/Arrow.dom.RecordBatchReader.html), [Arrow JS Vector v21.2.0](https://arrow.apache.org/js/current/classes/Arrow.dom.Vector.html), [Arrow columnar specification](https://arrow.apache.org/docs/format/Columnar.html), [ECMAScript JSON.stringify](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.stringify), [ECMAScript safe integer bound](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer), [Fetch Standard](https://fetch.spec.whatwg.org/), and [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html).

The selected source packet describes repository commit `f01ff0f`; this shared checkout is at `28c5ac2`. I checked the decisive type, project, provider, filter, evaluator, and planner claims against the current checkout. Application performance, allocation totals, real browser support, database behavior, and hosting behavior remain unmeasured.

## Dispositions

| ID | Source status → disposition | Review, evidence, and uncertainty |
| --- | --- | --- |
| CT-001 | adopt | Require authoritative snapshot, row domain, schema, scope, coverage, counts, and completion before decoding into application state. The local evaluator revision is tied to table-array object identity; it cannot identify a remote source snapshot. The current result type has no remote completion or coverage contract. Sources: raw §§3.4–3.5, 8; `AnalysisProject.ts`, `evaluateProject.ts`, `CrossfilterWrapper.ts`; [Arrow schema/format](https://arrow.apache.org/docs/format/Columnar.html). Uncertainty: query and adapter tracks must choose the canonical descriptor and source consistency mechanism. |
| CT-002 | investigate | Keep Arrow IPC stream with internal compression off and HTTP gzip as the binary candidate. The official JS API supports async record batches, but that does not prove a whole-path gain. The current provider needs rows, so decoding and row creation remain in the comparison. Sources: raw §§4, 7, 10; `ExplorEdaProject.tsx`, `DataLayerProvider.tsx`; [Arrow reader](https://arrow.apache.org/js/current/classes/Arrow.dom.RecordBatchReader.html). Uncertainty: benchmark server assembly, bundle startup, decoding, strings, row materialization, provider/chart work, and memory on the target browser. |
| CT-003 | adopt | Keep lossless row JSON as the simpler benchmark baseline. Do not ship it as an automatic runtime fallback or alongside Arrow by default; the authorized shape calls for a benchmark, then one production choice. Current consumers already accept rows. The ECMAScript rules confirm that bare `JSON.stringify` changes or omits undefined, nonfinite values, signed zero, and BigInt. Sources: raw §§4, 6, 10; `AnalysisProject.ts`, `projectFile.ts`, `DataLayerProvider.tsx`; [ECMAScript JSON.stringify](https://tc39.es/ecma262/multipage/structured-data.html#sec-json.stringify). Uncertainty: the comparison still needs an explicit lossless representation and value corpus; no JSON transport codec exists here. |
| CT-004 | adopt | Decode and validate outside the provider, build the row result once, then publish one complete snapshot. The provider's `setData` builds profiles, converted data, Crossfilter, and calculations; the data effect may restore saved state. Repeated publication would charge setup more than once. Sources: raw §§3.2, 7; `DataLayerProvider.tsx`, `ExplorEdaProject.tsx`. Uncertainty: exact helper and renderer allocation behavior is not visible in the report packet; measure in the runnable app. |
| CT-005 | adopt | Use a single compression layer by default and measure gzip, moderate Brotli, and identity where useful. Keep HTTP content coding separate from Arrow IPC internal compression. Sources: raw §§4, 5.9, 9; [Fetch Standard](https://fetch.spec.whatwg.org/), [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html), [Arrow format](https://arrow.apache.org/docs/format/Columnar.html). Uncertainty: winning settings depend on source data, hosting CPU, network, and browser; docs do not establish those measurements. |
| CT-006 | adopt | Treat byte preservation and consumer support as separate gates. Preserve the source value or report unsupported semantics before coercion. Current `AnalysisScalar` has no BigInt/decimal/nested form; current date and number parsing also imposes behavior. Sources: raw §§6.2, 10; `AnalysisProject.ts`, `valueParsing.ts`, `evaluateProject.ts`; [ECMAScript safe integer bound](https://tc39.es/ecma262/multipage/numbers-and-dates.html#sec-number.max_safe_integer), [Arrow schema](https://arrow.apache.org/docs/format/Columnar.html). Uncertainty: the accepted field subset and operations belong to query/adapter parity proof. |
| CT-007 | investigate | Compare dictionary, null, and validated integer-width savings after HTTP compression and the row bridge. Keep float64 for existing JS numbers unless source typing proves narrower values exact. Sources: raw §§5–6; [Arrow format](https://arrow.apache.org/docs/format/Columnar.html); `valueParsing.ts`, scatter planner. Uncertainty: byte arithmetic supports candidate experiments but no workload compression, build cost, startup, or decode result has been measured. |
| CT-008 | adopt | Budget wire, decoded payload, retained client state, peak replacement, and allocation/copy costs separately. Existing provider and chart paths keep profiles, field maps, Crossfilter, evaluation, and chart records beyond the transport buffer. Sources: raw §§3, 7, 9; `DataLayerProvider.tsx`, `evaluateProject.ts`, `scatterPlan.ts`, `barPlan.ts`. Uncertainty: 64/128/256 MiB and 100k rows are research knobs only. Calibrate against target browser, actual widths, keys, charts, and native-memory blind spots. |
| CT-009 | adopt | Use a predeclared paired end-to-end comparison with correctness first, then latency or peak-memory benefit and regression guards. The packet reports no application or codec measurements. Sources: raw §§1, 10; [repository performance guidance](../../../performance-checks.md). Uncertainty: 20%+100 ms, 25% memory, and small/interactions guards are proposed experiment rules, not user SLOs. Their practical value must be reviewed after measurement. |
| CT-010 | adopt | Bind any snapshot extension to one authoritative snapshot, row domain, order/key rules, schema and projection. Begin with a single completed snapshot; do not build a general progressive cache. `CrossfilterWrapper.ts` shows that linked, local, and workspace populations differ; row counts alone do not establish equivalence. Sources: raw §§3.4–3.5, 8.3; `evaluateProject.ts`, `ExplorEdaProject.tsx`, `CrossfilterWrapper.ts`; [Arrow format](https://arrow.apache.org/docs/format/Columnar.html). Uncertainty: whether later column extension is valuable, and whether an adapter can preserve a snapshot long enough, is unproven. |
| CT-011 | defer | Do not make Parquet the default dynamic query response. Keep it as a future option for existing immutable Parquet sources or repeated selective reads. Sources: raw §§4.1–4.2; [Parquet format](https://parquet.apache.org/docs/file-format/), [hyparquet](https://github.com/hyparam/hyparquet), [parquet-wasm API](https://kylebarron.dev/parquet-wasm/classes/esm_parquet_wasm.ParquetFile.html). Uncertainty: no chosen reader, source workload, browser bundle, or measured range-request path exists. |
| CT-012 | defer | Do not own a custom binary codec before standard Arrow overhead is isolated and shown to block the end-to-end goal. Sources: raw §§4, 6, 10; [Arrow format](https://arrow.apache.org/docs/format/Columnar.html). Uncertainty: custom startup and full maintenance cost have no prototype evidence; revisiting this now would add protocol design before proof. |
| CT-013 | adopt | Keep customer data, snapshots, dictionaries, and caches inside each dedicated customer instance. Hosting chooses the platform and proves memory, duration, streaming or bounded buffering, concurrency, cleanup, and automation. This comes from the direct customer-instance update. Sources: user update; raw §§1, 9, 11. Uncertainty: exact isolation boundary, platform, budget, state lifetime, and operating cost remain with the hosting track. |
| CT-014 | defer | Keep the existing row provider and Crossfilter for the format experiment. A column-store or Crossfilter rewrite would confound transport cost with a broad consumer change. Sources: raw §§3, 7, 10; `DataLayerProvider.tsx`, `CrossfilterWrapper.ts`, `scatterPlan.ts`, `barPlan.ts`. Uncertainty: provider/index/trace may dominate both encodings; measure and shape a separate narrow consumer change only if that occurs. |
| CT-015 | investigate | Investigate compact aggregate JSON as a distinct result shape, with same-snapshot trace capability or a clear limitation. Current aggregate evaluation retains stage and contributor records, so output group count alone does not define payload cost. Sources: raw §§3.6, 5.7, 10.3; `evaluateProject.ts`, `aggregates.ts`, `ExplorEdaProject.tsx`. Uncertainty: future remote aggregate/trace contract and source-snapshot retention are not defined. It is not part of the first scatter codec decision. |
| CT-016 | reject | Reject blanket end-to-end zero-copy claims. The Arrow vector API includes array conversion, current project code creates row objects, and provider/chart paths build additional indexes and point records. Sources: raw §§3, 7; `ExplorEdaProject.tsx`, `DataLayerProvider.tsx`, chart planners; [Arrow Vector](https://arrow.apache.org/js/current/classes/Arrow.dom.Vector.html), [structured-clone/transfer rules](https://html.spec.whatwg.org/multipage/structured-data.html). Uncertainty: particular boundaries may still avoid a copy; prove each with an allocation and ownership measurement. |

## Shared contract for the other tracks

Transport needs one bounded complete result to identify the customer instance, authoritative source snapshot, query and population scope, row grain, typed keys/order, schema, row and field coverage, count meaning, and successful completion. The query track owns demand and filter scope. The adapter track owns source consistency, type exposure, materialization, and cancellation. The hosting track owns resource limits, data locality, and instance lifecycle. The transport proof counts row consumers and old/new snapshot overlap on each dedicated instance.

No format is selected for production yet. Compare Arrow and lossless compressed row JSON with the same result and consumer behavior. Ship one encoding only after a correctness and capacity pass plus the stated end-to-end gate. No performance or memory result is available today.

See the [shared reconciliation](../../../research/database-backed-analysis-2026-10-11/reconciliation.md) for the agreed boundaries across all four tracks.
